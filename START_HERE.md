## 5. Interview-chance model (all constants in `engine.ts` FACTORS and `fit.ts`, every one has a source)
Base rate by category (Ashby 2026, SmartRecruiters 2025) x origin (0.76 / 0.93) x internship (1.126) x referral (1.49) x tailored CV (1.31 high end), then the CV fit (skills by requirement tier 40%, role 40%, level 20%; average 0.4) moves the chance between "fitted" anchors 18-54% (Thijssen et al. 2019) and lower (Bertrand and Mullainathan 2004). No profile data = 0% with "Add your CV or connect LinkedIn". Dashboard odds = 1 - product(1 - p) over applied jobs; job odds = interview chance x 0.81 / 3.25. Tiers: must 1, strong 0.7, optional 0.4, nice 0.2, unspecified 0.6.

## 10. Profile facts and track record (built 2 Oct 2026)
**How it works.** The saved profile in the database (`profiles.data`) is the source of truth. Edge Function `read-profile` cuts it into parts (each role, each degree, each CV line: `supabase/functions/read-profile/items.ts`), asks TypeSafe Jev four closed questions per part (employer/position standing, prize tier, grade tier, line of work: `judge.ts`), and stores the answers in `profile_facts` keyed by a fingerprint of the part's text. An unchanged part is never read again; an edited or new part is read the next time the function runs; a removed part stops counting. The app (`src/lib/use-profile-facts.ts`) calls it after every profile save and on sign-in, and uses a stored fact only if its part still exists in the current profile. `src/lib/strength.ts` turns the facts into a lift for any job with plain rules (best part in full, second at a quarter, scaled by whether the part's line of work is the job's family or next to it). No Jev call per job. Strength only lifts the fit (`STRENGTH_PULL`), never lowers it, and adds no multiplier: the chance stays inside the sourced 18% to 54% top.
**Assumed, not measured:** the tier values, which families are neighbours, `STRENGTH_PULL`, the field weights (`FIT_WEIGHTS_FIELD`), `SKILL_PRIOR`. Say so on the page; do not present them as findings.
**Field match** (`src/lib/field.ts`): which line of work the profile points to, counted from the postings' Jev families (`scripts/make-family-model.ts` writes `family-model.json`; rerun after a new collection; `scripts/eval-family-model.ts` measured 75.6% right on held-out postings).
**Other fixes the same day:** degree reading (`degree.ts`, many countries' names, Scrum Master no longer a master's), robust CV dates, a Language gate from job titles (`languages.ts`), skills evidence-weighted.
**Secrets:** `TYPESAFE_API_KEY` is an Edge Function secret (set via the Management API, never in a file). `.env.secrets` still does not exist; the Supabase `sbp_` token and the Jev key were pasted in chat and must be rotated (after rotating the Jev key, set the secret again or readings stop).
**Tests:** `bun test` (283), `scripts/check-students.ts` (23 international-student profiles, answers written down), `scripts/check-profile-facts.ts` (live Jev, needs the key: 18 known entries x3 + every student entry), `src/lib/read-profile-function.test.ts` (the real function against a fake backend). **Not yet tested:** a real signed-in account end to end (no account exists; do not create one on the live project).
