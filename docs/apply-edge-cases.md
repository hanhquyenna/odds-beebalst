# Apply edge-case audit

Date: 2026-10-19. Scope: both Apply entry points through the extension, the MCP drive queue, and Broods.

## End-to-end paths

**Web app button**

`src/components/OddsApply.tsx` `beginApply` sends `apply` to the extension (embedded through `panel-frame.js`, or the page bridge through `prepareInExtension`). `background.js` handles `apply-in-tab`, deduplicates with `applicationStarts` and `oddsApplyIntents`, opens or resumes one tab in `openApplication`, and injects `apply.js` (LinkedIn) or `apply-any.js` (other sites). Deterministic extension rules fill first. The content script calls `/ext/drive-start`, polls `/ext/drive-next`, executes `drive_commands`, and posts `/ext/drive-result`. `drive.ts` starts `odds-apply` in Broods. Broods calls the same edge function as MCP tools until it calls `finish`.

**Side panel button**

`src/components/ApplyPanel.tsx` `OddsButton` sends one of:

- `panel-fill`: `panel-frame.js` -> `background.js` `fillTab` -> `odds-fill-now` -> `apply-any.js`.
- `apply-here`: `panel-frame.js` -> `background.js` `applyHere`; the current tab becomes the application tab.
- `panel-account`: `panel-frame.js` -> `accountInTab`; the account step runs in the current tab and retains the same `driveRun`.
- `panel-add-job`: adds/reads the job, refreshes panel info, then the person can apply.

Both paths converge on `apply-any.js` / `apply.js`, `drive_runs`, `drive_commands`, and the one Broods agent.

## Failure and recovery audit

“Fixture” names below are existing Playwright tests in `e2e/extension.spec.ts`. “Unit” names are under `src/lib`.

| Edge case | Evidence and can it hang? | Reproduction / coverage | Resolution |
| --- | --- | --- | --- |
| Quick tunnel dies but `cloudflared` stays alive | `scripts/launchd/run-tunnel.ts` owns the quick tunnel; Broods uses its `/v1` URL. Before this change, register errors and a dead models endpoint could leave the old URL deployed. Runs could remain Filling. | Unit: `tunnel health` covers register errors, 401 reachability, and the 60s threshold. | **Fixed:** restart on `Tunnel not found`, `Register tunnel error`, or 60s failed health. Deploy only a URL that passed `/v1/models`. |
| Mac sleeps/wakes or changes Wi-Fi/Ethernet | A quick tunnel commonly loses its edge connection while timers are suspended or the route changes. Waiting for the ordinary 60s health window is avoidable. | Unit: `a sleep gap restarts immediately after wake`; `a usable network change or return from offline restarts`. | **Fixed:** a monitor gap of 20s restarts immediately after wake; a non-empty network fingerprint change or the return of a usable network restarts immediately. Offline-to-offline does not churn. |
| Old and new tunnel deploys race, or Broods deploy fails | `pointBroods` used to be fire-and-forget from stderr. A slow deploy for URL A could finish after URL B and put Broods back on A; a failed deploy could leave the old URL indefinitely. | Unit/source guard: `a quick tunnel is deployed only after its public models endpoint is reachable`. | **Fixed:** one serialized `wantedBase` loop. Stale URLs are skipped before env set, before deploy, and before saving. An unhealthy URL is never deployed. Environment/deploy failures retry every 30s while the URL is current. |
| Broods accepts 202, then the model fails | `drive.ts` `startBroods` formerly treated `runAsync` acceptance as a start. The incident failed in about 60ms with `model.invocation.failed` / `ENOTFOUND`. | Unit: `a failed or unreachable model is a start failure`. | **Fixed:** poll `getAsyncStatus` for 2.5s; failed/expired/not-found and network/model errors set `drive_runs.status=stuck` with `Broods' model is unreachable`. |
| Broods turn completes without one browser tool | An async run can become `completed` while `drive_runs` still says running. No command means the tab has nothing to execute. | Unit: `a turn that completes before sending a tool is checked for zero commands`. | **Fixed:** completed start plus zero non-recipe commands is immediately stuck with a retry message. Later zero-command quiet runs get the unreachable message after retries. |
| Broods becomes quiet after sending commands | `drive.ts` checks `updated_at` after `QUIET_MS`; a turn can die after a command or omit `finish`. | Unit: `quiet give-up`; fixture: `ACCEPT: empty page never silent-fills`. | **Covered:** three fresh-conversation retries, then generic Stuck. Open commands are cancelled. |
| The extension drive loop receives successful idle forever | Server responses can contain neither `command` nor `done`, especially across a deployment mismatch. | Unit: `two minutes of idle with no command gives up`. | **Fixed:** `apply-any.js` changes the tab to needs input after two minutes of successful idle. Transport loss has its separate five-minute recovery path. |
| Service worker sleeps | Manifest V3 workers stop between events. In-memory maps disappear, but a message/port wakes the worker. `oddsApplyIntents` and application runs are in Chrome storage; each `drive-next` request is finite (20s). | Fixtures: `Continue after a reload resumes the same tab`; `Apply background + Open tab edge cases`; `STRESS: six applications at once`. | **Covered:** persistent intents, reinjection on failed ping, serialized storage writes, finite long-poll. No permanent worker-held lock. |
| Browser restart or extension update invalidates content scripts | `onStartup` / `onInstalled` cleared intents. Previously their server `drive_runs` could remain running with no owner until another start cleaned them. | Unit/source guard: `browser and extension restarts stop stored drive runs before intents are cleared`. | **Fixed:** stop every stored `driveRun`, then clear intents. A fully offline browser still relies on the 30-minute server lease; see “scheduled reaper” below. |
| Tab closes | `background.js` `tabs.onRemoved` sends `drive-stop` and removes the intent. `drive-stop` cancels queued/taken commands. | Fixture: `the person fills ... closing the tab stops the run at once`; unit: drive status tab-close cases. | **Covered:** immediate stop when Chrome can send it. Review remains review so the app can ask whether it was sent. |
| Tab reloads or a site navigates after Next | A new document must not accept the old document's result. `fresh` increments `doc_gen`; old taken work is requeued/cancelled and results are CAS checked. | Fixtures: `OWNERSHIP: fresh/reload bumps doc_gen`; `Continue after a reload`; unit: `canAcceptDriveResult`. | **Covered:** generation ownership and stale-result rejection. The run id follows the tab in storage. |
| Person types a different URL or uses a bookmark | Continuing would fill personal data on an unrelated page. `webNavigation.onCommitted` calls `personTookTab`. | Fixture: `the person takes the application tab for something else`. | **Covered:** stop the drive run and retain a needs-input record that says why. |
| Opening or reinjecting the application page fails | `oddsGo`, script injection, and `application-continue` previously swallowed errors in several paths, leaving Filling. | Unit/source guard: `failed navigation, reinjection, and panel fill become visible failures`. | **Fixed:** web and panel navigation failures become `failed`; reinjection is pinged and failure is stored; panel-fill failure becomes visible panel status. |
| Background-tab throttling or a minimized window | Hidden tabs can be heavily throttled and `captureVisibleTab` cannot see a minimized/covered window. `openApplication` creates an active tab in the person’s window or the reusable Odds window. Screenshot returns a clear error while `read_page` remains available. | Fixtures: `a job queued from the phone is driven by Broods in the Odds window`; `Apply does not steal focus`; `acts by sight`. | **Covered for normal use. Larger:** Chrome may freeze an entirely occluded/minimized window. Add a lightweight offscreen heartbeat and surface “tab suspended” when it misses two leases. |
| Prerender/warmup or script loaded before intent | A content script can start before `setIntent`, especially on a new tab. New tabs await intent before the opener is removed, then send `application-continue`. DOM observers handle late forms. | Fixtures: `classic LinkedIn search inside preload`; `Broods fields a click reveals`; `delayed fields`. | **Covered:** intent-before-navigation for owned tabs and explicit wake after transfer. Chrome prerender pages that disallow extension execution remain a platform limit and should fall into failed injection, not Filling. |
| ATS iframe or same-origin blank iframe | The top page and frame could both drive, or neither could. `apply-any.js` selects known ATS frames and blank frames with at least three controls; the top page steps aside. | Fixtures: `embedded Greenhouse form`; `blank frame (HubSpot-style embed)`. | **Covered. Larger:** arbitrary cross-origin forms outside manifest host access cannot be read. Request host access on demand and state which frame was blocked. |
| Shadow DOM form | Native selectors do not cross every closed shadow root. Open shadow roots are walked by the extension helpers; closed roots are browser-internal. | Fixture: `form built from components with shadow roots`. | **Covered for open roots. Larger:** use Chrome DevTools Protocol DOMSnapshot for closed component trees, while preserving the same submit/password guards. |
| Popup/new tab opens from Apply | `followFrom` transfers the intent. Side-panel “same tab” waits up to 6s for a real HTTPS URL and folds it back into the opener. A slow blank popup previously returned silently. | Fixture: `Broods clicks a job that opens in a new tab`. | **Fixed:** a popup that never gets a URL, or cannot be folded back, becomes needs input with instructions. |
| CV input is lazy, replaced, or cleared after AJAX upload | A plain `input.files` check is insufficient. The extension catches a newly created picker and recognizes successful attachment UI after the input is cleared/replaced. | Fixtures: LinkedIn lazy uploader; Hunkemöller picker; Lever AJAX upload; Teamtailor fresh input; French Workday resume stress. | **Covered:** upload is verified from page state and failed upload cannot become Review. Closed/native OS pickers that Chrome cannot attach remain human. |
| Account or captcha wait | Odds must not type passwords or solve captcha. A wait can look like a hang if no resume signal follows. `watchPerson` and captcha disappearance call `drive-continue`; `resumeRun` is capped. | Fixtures: LinkedIn/Indeed/Glassdoor login walls; captcha carry-on; side-panel account flow. | **Covered:** distinct needs-you reasons and automatic resume. **Fixed:** panel-account retains the same `driveRun`; a failed account action now becomes needs input instead of Filling. |
| Closed job, wrong job, or board search page | A board redirect can resemble a closed listing; a foreign employer must not receive data. | Fixtures: closed LinkedIn; 404 closes job; Glassdoor search result; wrong-job host; unit `jobIdentityMismatch`. | **Covered:** closed evidence is required; wrong host stops as Wrong job; board search is not a form. |
| Two frames or two starts in one tab | Top page and ATS frame can call start together. | `background.js` `driveStarts` joins starts per tab; `drive-start` also joins an exact recent page. Fixture: `OWNERSHIP: duplicate poll claims the same command only once`. | **Covered:** one promise per tab and command CAS. |
| Web button and panel button, or two tabs, start the same posting | `openApplication` deduplicates by posting/canonical URL and removes duplicate intents. `applyHere` intentionally owns the current tab, so a simultaneous existing run on another tab can still create a second server run. The newest run wins in the tracker, but both agents may work. | Unit: `newest run wins`; fixtures: `one click opens one tab`; `two phone requests`; stress multi-tab. | **Partial, larger fix:** add a server-side `acquire_drive_run` RPC under a per-user/posting advisory lock. Return the existing owner or explicitly transfer ownership, stop the old run, and cancel its commands atomically. Do not add only a unique index because jobs without `posting_id` and deliberate restarts need an ownership policy. |
| Stale run blocks or outlives the tab | `live()` includes `expires_at`, but an expired row formerly stayed `status=running` in the database. If Chrome crashed while offline, no close event reaches the edge. | Unit: `an expired running lease is terminal`; source guard: expired run cancellation; drive-status stale heartbeat test. | **Fixed on next poll:** expired running row becomes Stuck and open commands are cancelled. **Larger:** schedule a Supabase lease reaper (for example every minute) to settle running rows whose `expires_at` passed or whose `last_seen_at` is older than 10 minutes, covering a total browser/Mac crash with no later request. |
| Extension and edge versions do not agree | Content script reinjection recovers an extension reload, but there is no explicit protocol version in `drive-start` or `drive-next`. Shape changes can yield successful HTTP with unusable fields. | Existing fixture: reload resumes; proposed fixture: fake edge returns `min_extension_build` above manifest and expects needs input. | **Larger:** send `APPLY_BUILD` and a numeric drive protocol on every route. Edge returns `426` plus required build; background stores a clear “Reload Odds” state. Keep one previous protocol during rollout. |
| Edge/auth/network request fails | `ask`/`ext` can return null. `apply-any.js` distinguishes transport loss, retries with backoff, then asks the person after five minutes. Start failure asks immediately. | Fixture: `connection drops while Broods drives`. | **Covered:** no successful-idle confusion. Five minutes is deliberately longer than a transient service-worker/tunnel restart. |
| Command is taken but result is lost | A content script can unload after taking a command. MCP waits 25s, expires/cancels it, and asks Broods to `read_page`; duplicate/late results are rejected. Two never-started commands become needs you. | Unit: ownership tests; fixtures: delayed result rejected, duplicate poll, fresh generation. | **Covered:** finite command lease and CAS. A server push channel could reduce the 25s worst case. |
| Panel button itself stays pressed | `panel-fill` used to set `pressed` forever if no status arrived. Other panel actions already had short local timers. | Unit: `panel-fill press expires after 30s`. | **Fixed:** local 30s fallback, while real extension state remains authoritative. |
| `panel-add-job` fails | This action is finite: it returns an error, refreshes panel data, and the button’s own 2.5s timer clears. It does not create a drive run. | Existing panel/add/read fixtures; proposed fixture: add endpoint 500 leaves “Track this job” enabled. | **No forever run.** Improve later by showing the returned add error inline rather than only resetting. |
| LinkedIn Easy Apply gets healthy idle responses forever | `apply.js` `driveModal` had the five-minute transport-loss bound but not `apply-any.js`'s bound for successful responses with no command. A model turn that ended without a tool could therefore leave the LinkedIn bar filling forever. | Unit/source guard: `LinkedIn Easy Apply surfaces a healthy but commandless Broods run`; targeted LinkedIn fixtures. | **Fixed:** both drivers surface `Broods' model is unreachable` after two minutes of healthy responses without a command. |
| Web app is hidden or extension status delivery stops | `OddsApply.tsx` pauses status polling while `document.hidden`; `content-site.js` and `panel-frame.js` ignore `runtime.lastError`. `application-progress` is fire-and-forget. If the worker and page timers are both throttled, the app chip can be stale even while the server run progresses or stops. | Proposed unit: failed `application-status` callback and hidden-to-visible refresh; proposed fixture: `sw-sleep-hidden`. | **Can look hung, not an unbounded server run. Larger:** refresh immediately on `visibilitychange`, return an explicit disconnected status on `lastError`, and add the worker/tab heartbeat below. |
| Embedded web Apply has no correlated acknowledgement | The site bridge uses a request id and a 10s handshake, but embedded `OddsApply` posts `apply` without waiting for a correlated response. A missing parent bridge can leave local activity saying it started before any tab exists. | Proposed `extension-connect` test: missing/late parent response; fixture: embedded Apply with panel bridge disabled. | **Can silently stop before a run exists. Medium:** use the same request-id handshake for embedded and site paths, and only create apply activity after the extension acknowledges ownership. |
| Intent arrives late, expires, or has no posting id | `apply-any.js` waits about 6s for an intent and a non-forced launch can exit quietly. `background.js` treats intents older than one hour as absent and `liveApplicationStatuses` omits intents without `postingId`, although the content script may still exist. | Proposed fixtures: `intent-late`; unit: status for an anonymous or expired intent. | **Can make the tracker go silent. Medium:** persist a visible attach failure after the quiet wait, settle expired intents and their drive runs, and track URL-keyed runs when no posting id exists. |
| Person leaves the owned tab | `personTookTab` stores a `left-*` needs-input record, but `application-status` returns null when the original tab no longer exists and the status is not submitted/failed. The tab is safely stopped, while the job-detail chip can disappear. | Existing fixture: `the person takes the application tab for something else`; proposed status API unit for `left-*`. | **No agent hang, partial UI gap:** include paused `left-*` records in status lookup until dismissed or superseded. |
| Losing tab survives posting deduplication | `openApplication` removes a duplicate tab's intent. Removal alone does not guarantee an already injected content script has stopped its server run, so simultaneous web/panel or two-tab starts can briefly leave an orphan driver. | Proposed background test: two tabs with the same posting, both already started; verify losing `driveRun` receives `drive-stop`. | **Can duplicate work. Medium:** as part of atomic ownership, stop/cancel the losing run before deleting its intent and tell that tab it lost ownership. |
| Side panel is disconnected or has no page | After its splash, `ApplyPanel.tsx` returns null when the bridge is disconnected, the page is unsupported, or the person selected My jobs. `toExtension` is fire-and-forget, so action failures such as missing connect credentials are not rendered directly. | Proposed component tests: disconnected bridge, unsupported page, and rejected `apply-here`; existing polling fixtures cover normal state. | **Can look blank or silently reset. Medium:** distinguish intentional My jobs from disconnect, render reconnect/unsupported-page copy, and correlate action replies. Background-side failures are now stored when an intent exists. |
| Side-panel fill starts in a framed form | Full apply discovers and hands off known ATS/blank frames, but `panel-fill` sends `odds-fill-now` to the top document. An embedded ATS form can be visible yet the panel action finds no controls. | Existing embedded Greenhouse apply fixture; proposed `panel-fill + iframe` fixture. | **Can stop without filling. Medium:** reuse the `apply-frames` frame-selection and handoff path for `panel-fill`; show the blocked frame origin when host access is missing. |
| Mid-run output schema or turn limit ends Broods | `broods/index.ts` requires an `apply_pick` structured output while drive mode says every turn must call a tool until `finish`; `maxTurn: 90` is below the edge `MAX_STEPS: 120`. A JSON-only turn or model turn cap reaches the edge only as quietness. | Quiet retry units cover eventual settlement; proposed Broods eval: drive turn emits structured output without a tool; proposed 90-step fixture. | **Finite but delayed:** edge retries and then marks Stuck. Larger: split pick and drive agents/output schemas, align limits, and have Broods report an explicit terminal turn event. |
| Active run reaches its 30-minute lease | `expires_at` is renewed by `resumePatch`, not on each successful command. A long but active application can cross the lease while commands and heartbeats are still healthy. The MCP tool route returns an error when a run is no longer live; the extension poll now settles it. | Proposed unit: active command near lease boundary extends lease; integration test: expired MCP tool call and `drive-next` agree on terminal status. | **Can stop a long run unexpectedly, not forever. Small proposal:** renew a bounded lease on accepted command results or heartbeats; keep the scheduled reaper for abandoned runs. |
| Layer timeouts disagree | The app labels a run Waiting after 15s, server quiet detection is 30s, command leases can wait 25s, extension long-poll is 20s, generic healthy idle is 2m, and transport loss is 5m. These are different failure classes, but their copy can make a live retry look stuck. | Timing units for quiet/idle; proposed contract test asserting the intended ordering. | **No infinite wait after current bounds. Small proposal:** export a shared timing contract where possible and show `Retrying Broods` separately from tab/person waits. |
| Invisible captcha, closed shadow root, or native picker | Text/DOM inspection cannot reliably identify invisible captcha challenges, closed component internals, or native dialogs. Existing guards refuse captcha/password/submit, but absence from `read_page` may look like an unexplained blocker. | Existing captcha, shadow, and lazy CV fixtures cover visible/open cases; proposed fixtures for invisible challenge and closed-root consent. | **Finite through quiet handling. Larger:** frame/CDP diagnostics and explicit “browser-only control” handoff, never captcha solving or native picker automation. |

## Remaining proposals, ordered by impact

1. **Atomic run ownership.** Implement `acquire_drive_run(user, posting, canonical_url, tab, protocol)` as a transaction/advisory lock. It should join the same tab, or stop/cancel and transfer from another tab. This closes the remaining web-button versus panel-button race.
2. **Scheduled lease reaper.** Settle expired and heartbeat-dead rows even when the Mac and Chrome disappear together and never make another request.
3. **Drive protocol negotiation.** Send extension build/protocol, support current and previous versions, and return a visible upgrade response rather than relying on object shape.
4. **Frame access diagnostics.** Report the blocked frame origin and offer a host-permission request. Add CDP DOMSnapshot for closed shadow roots.
5. **Worker/tab heartbeat.** Store a small heartbeat in `chrome.storage.session`; surface suspended/minimized/energy-saver state after two missed command leases.
6. **Unify Apply acknowledgements and status.** Correlate embedded and panel actions, retain URL-keyed status without a posting id, and return paused/off-tab records rather than null.
7. **Separate Broods pick and drive contracts.** Do not require `apply_pick` output from the tool-only drive loop. Align its turn cap with the edge step cap and report terminal turns explicitly.

## Why Broods is slower or less capable than an in-browser agent

The model stays on 9router on the Mac. These improvements keep that architecture.

| Gap | Current cost/evidence | Improvement while keeping 9router |
| --- | --- | --- |
| Per-command round trips | Every Broods tool call travels Broods -> edge MCP -> `drive_commands` -> extension long poll -> DOM action -> `drive-result` -> edge -> Broods. MCP waits up to 25s (`TOOL_WAIT_MS`), while the extension long-polls up to 20s (`NEXT_WAIT_MS`). Normal commands are faster, but each still pays several network and database hops. | Add a WebSocket/SSE channel from extension to the edge with long-poll fallback. Batch safe sequences (`read + fill known fields`, or several independent fills) and return the fresh page in the same result. |
| Polling delay and service-worker wakes | The extension repeatedly calls `drive-next`; a sleeping worker and HTTP setup add latency. | One push connection owned by an offscreen extension document can wake the worker only for a command. Keep stored command leases and CAS as fallback. |
| Text-first page understanding | `read_page` sends structured text, fields, buttons, errors, and headings. It is cheap and safe, but misses layout, canvas, closed shadow DOM, and unlabelled visual controls. | Keep text-first. Automatically attach one compressed screenshot plus DOM bounding boxes only after `read_page` reports a blocker or a fill fails. Cache a perceptual hash so unchanged screenshots are not resent. |
| Screenshot limitations | `captureVisibleTab` needs a visible, non-minimized tab. Broods gets one screenshot per problem by policy. Claude in Chrome is already colocated with the rendered page and can inspect continuously. | Keep the application tab active in the Odds window; add CDP `Page.captureScreenshot` where permission allows, and surface visibility failures immediately. |
| Stale page snapshots | Between model choice and command arrival, React/Workday can redraw and field ids can move. The drive protocol uses `doc_gen` and stable structural ids, but another model turn may be needed. | Return a compact DOM delta and remap key with each command. Permit guarded “fill by label + expected options” so the extension can re-resolve locally without another model call. |
| Model cold start through quick tunnel | A wake or network change requires a new Cloudflare URL and a Broods env/deploy update. During that interval calls fail. | The self-healer now restarts immediately and serializes URL deploys. Next improvements: keep 9router warm with a local `/health` check, record tunnel/deploy latency, and preflight the public `/v1/models` endpoint before the UI starts a Broods run. A named tunnel would remove URL rotation, but is intentionally only documented for now. |
| Too many model turns | Broods may alternate `read_page`, one action, and another read. The in-browser agent can inspect and act in one local loop. | Expand deterministic extension rules and site playbooks; allow the model to return a short guarded plan of non-submit actions that the extension executes until a precondition changes. Keep Submit/password/captcha guards in the extension. |
| Limited local memory | A Broods retry is a new conversation to escape a hung model request. It rereads the page and can repeat reasoning. | Include the last successful page hash, last two tool outcomes, failed field methods, and playbook result in the resume payload. This is small, non-PII state and reduces repeated reads. |

## Invariants

- The extension remains the hands and enforces never Submit, never passwords, and never captcha solving.
- Broods remains `odds-apply` on `cx/gpt-6-luna` through 9router on the Mac.
- A quick-tunnel outage may delay a run, but an active extension surfaces Stuck/needs-input through start-status checks, zero-command quiet handling, idle timeout, or lease expiry. A total Mac/browser disappearance is hidden after the heartbeat goes stale; the proposed scheduled reaper is still needed to change that offline database row from `running`.
- The side panel and web button converge on the same drive protocol and status rows.
